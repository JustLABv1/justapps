This page is the shortest path from an empty host to a usable JustApps administration account. For a production deployment, read the [Docker Compose](./deployment/docker-compose) or [Helm](./deployment/helm) guide first.

## Choose an installation path

| Situation                                           | Recommended path                              |
| --------------------------------------------------- | --------------------------------------------- |
| One VM or single host with PostgreSQL               | [Docker Compose](./deployment/docker-compose) |
| Kubernetes cluster, ingress, and persistent volumes | [Helm](./deployment/helm)                     |
| Local development from source                       | The development steps below                   |

| Requirement                                              | Version            |

| [Keycloak](https://www.keycloak.org/) _(optional)_       | Any recent version |

## Quick install with Docker Compose

If you want a full installation on a single machine without Kubernetes, use the checked-in Compose stack:

```bash
git clone https://github.com/JustLABv1/justapps.git
cd justapps/deploy/compose
cp .env.example .env
# Replace the placeholder secrets in .env before using this outside a test host.
docker compose up -d
```

This starts PostgreSQL, the backend, the frontend, and the documentation service. By default, OIDC is disabled so you can create the first local user at `http://localhost:3000` without Keycloak. The first locally registered user becomes an admin.

For production-style settings, edit the Compose environment before starting. For Keycloak setup, see [Authentication](./authentication). For container details, see [Docker](./deployment/docker-compose).

If you want a single public hostname such as `https://apps.justlab.app`, enable the optional NGINX edge proxy described on the [Docker](./deployment/docker-compose) page.

## Local development

### 1. Clone the repository

```bash
git clone https://github.com/JustLABv1/justapps.git
cd justapps
```

### 2. Configure the backend

```bash
cd services/backend
# Review config/config.yaml and set repository_provider_encryption.secret.
# See the Configuration guide for the complete example.
```

### 3. Start the backend

```bash
go mod download
go run main.go --config config/config.yaml
```

The API is available at `http://localhost:8082` when `port: 8082` is used in the config file.
The backend auto-runs all pending database migrations on startup.

### 4. Configure the frontend

```bash
cd services/frontend
# Configure .env.local if needed — see the Configuration guide
```

### 5. Start the frontend

```bash
pnpm install
pnpm dev
```

The app is available at `http://localhost:3000`.

### 6. Start the documentation service

In another terminal:

```bash
cd services/docs
pnpm install
pnpm dev
```

The documentation service is available at `http://localhost:3001/docs`. The frontend rewrite also makes it available at `http://localhost:3000/docs`.

## First Login

If OIDC is **disabled**, register the first local user through the frontend at `http://localhost:3000/register`. The backend assigns the first registered local user the `admin` role automatically.

If OIDC is **enabled**, log in via Keycloak. See the [Authentication](./authentication) page for setup instructions.

## Verify the installation

```bash
curl http://localhost:8080/api/v1/health
curl -I http://localhost:3001/docs
```

The exact ports depend on the deployment path. Compose defaults to frontend `3000`, backend `8080`, and direct documentation access on `3001`; the bundled edge proxy exposes the frontend and docs from one hostname.

## What's running

| Service       | Port   | Purpose                 |
| ------------- | ------ | ----------------------- |
| Backend API   | `8082` | REST API (`/api/v1/*`)  |
| Frontend      | `3000` | Next.js web application |
| Documentation | `3001` | Fumadocs site (`/docs`) |
| PostgreSQL    | `5432` | Database                |
